# 文献推荐 V2 页面设计规范

> 绑定：`.ulpi/design/DESIGN.md`
>
> Every screen must read as the same product if placed side by side.

## 1. 设计结论

页面名称保持“文献推荐”。它不是新的检索中心，也不是复杂的证据分析工作台，而是一个简洁的增量候选页：根据当前研究和现有检索快照，推荐相关、尚未覆盖且适合当前研究问题的 PubMed 文献。

设计目标只有三个：

1. 用户能确认推荐基于哪个研究；
2. 用户能看懂每篇文献为什么值得关注；
3. 用户能判断它是不是当前集合中的新增文献。

## 2. 视觉方向

- 延续 `technical / utilitarian` 临床证据控制台风格。
- 使用现有左侧导航、背景、主蓝、字体、圆角和分割线。
- 页面签名元素是“推荐依据路径线”：`当前研究 → 相关度筛选 → 增量判断 → 推荐结果`。仅在生成中状态和结果摘要中出现，不做装饰。
- 页面采用标题区、依据条带、结果列表三种布局，不增加常驻右侧栏，不使用卡片套卡片。
- 唯一主操作是“生成推荐”。

## 4. 推荐依据区

### ResearchBasisPanel

目的：让用户确认推荐使用的研究上下文，不要求再次填写自由文本。

默认数据：

- 研究名称；
- 研究问题；
- `research_intent_id` 与版本；
- 当前 `result_id` 和检索策略版本；
- 当前快照文献数；
- 数据源，第一版固定显示 PubMed。

交互：

- “更换研究”打开现有研究选择器；
- 研究存在多个结果快照时，默认选择最近一次已完成快照，用户可以展开切换；
- 没有已确认 Research Intent 时，主按钮禁用，显示“先确认研究意图”；
- 不允许在此页直接编辑 PICO 或 MeSH，提供前往检索中心的次级链接。

### 推荐目标

第一版只提供三个选项，避免复杂：

| 模式 | 用户语言 | 排序重点 |
|---|---|---|
| `balanced` | 综合推荐 | 相关度60%、增量价值25%、证据适配15% |
| `latest` | 最新进展 | 保持相关度门槛，提高新近性权重 |
| `key_evidence` | 关键证据 | 保持相关度门槛，提高证据适配和开放影响信号 |

默认 `balanced`。推荐数量为5、10、20，默认10。

## 5. 推荐结果区

### 结果标题

显示：

- 新增候选数量；
- 被排除的重复或已覆盖数量；
- 生成时间；
- Recommendation Run 状态；
- 排序：推荐优先、相关度、最新发表。

“已覆盖文献”不占推荐名额，仅以“另有 N 篇已在当前结果中”的文本入口展示。

### RecommendationRow

桌面端使用 `30px + minmax(0, 1.55fr) + minmax(320px, .9fr)`。1024px 以下改为单列，推荐理由紧跟文献信息；640px 以下操作按钮全宽排列。

左侧固定顺序：

1. 排名；
2. 年份、期刊、研究类型；
3. 文献标题，最多三行；
4. 作者，最多两行；
5. 最多两个主题或研究类型标签；
6. PMID、PubMed链接；
7. 查看摘要；
8. 加入候选。

默认不展示 JCR、IF、Q区和完整评分。若合法期刊指标已导入，在“查看评分依据”中按可用状态展示。

右侧“为什么推荐”永久可见，分为三段：

```text
匹配当前研究
与人群和干预高度匹配

提供新增价值
补充长期安全性结局；当前结果中尚未覆盖

证据适配
随机对照研究，适合治疗效果问题
```

顶部只显示三个易懂信号：

- `相关度：高/中`，同时提供0–100数值的可访问说明；
- `增量价值：高/中/低`；
- `证据适配：高/中/不确定`。

不显示伪概率。信号缺失时显示“数据不足”，不显示0。

底部集合状态必须为以下之一：

- 新增候选；
- 已在检索结果；
- 已在阅读计划；
- 已在知识库；
- 疑似重复；
- 已忽略。

### 操作语义

- “加入候选”：保存到正式候选池，成功后变为“已加入候选”；
- “查看该文献”：若已在检索结果中，跳转对应结果并定位 PMID；
- “PubMed”：打开真实外部页面；
- “不感兴趣”：放入更多菜单，要求选择原因“重复/主题偏离/研究类型不适合/其他”；
- “加入阅读计划”和“保存到知识库”不作为默认主操作，进入候选后再处理。

## 6. 推荐逻辑和解释边界

第一版推荐分：

```text
priority = 0.60 relevance + 0.25 incremental_value + 0.15 evidence_fit
```

- `relevance`：Research Intent、PICO、MeSH、标题摘要词项匹配；
- `incremental_value`：不在当前快照、阅读计划和知识库中，且与已有文献不过度相似；
- `evidence_fit`：研究设计与问题类型匹配，例如治疗问题优先系统综述和RCT。

推荐理由必须来自持久化的结构化证据。LLM只能将证据改写为简短中文，不能决定候选集合、分数、重复关系或文献事实。

推荐项至少返回：

```text
run_id, pmid, citation,
priority_score,
relevance { score, level, evidence[] },
incremental_value { score, level, evidence[] },
evidence_fit { score, level, evidence[] },
overlap_status,
limitations[],
decision_status
```

OpenAlex总被引、年度引用、热度和文章影响力作为解释性开放信号，不替代三项主评分。JCR、IF、SCI/SCIE和Q区只在合法导入且精确匹配时展示。

## 7. 页面状态

| 状态 | 页面表现 | 可用操作 |
|---|---|---|
| 无研究 | 简洁空状态“选择研究后生成推荐” | 选择研究 |
| 无确认Intent | 显示缺失项，不渲染假推荐 | 前往确认研究意图 |
| 可生成 | 显示研究依据和配置 | 生成推荐 |
| queued/running | 依据区保持可见，路径线显示当前阶段，列表显示骨架 | 取消 |
| partial | 展示已完成结果和明确数据限制 | 查看、重试缺失信号 |
| completed | 展示新增候选和已覆盖摘要 | 加入候选、忽略 |
| zero-novel | “未发现新增候选，当前策略覆盖较充分” | 切换最新进展或重新检索 |
| failed | 保留上一版成功结果并提示本轮失败 | 重试、查看上一版 |
| offline | 保留已持久化结果，只读显示 | 网络恢复后重试 |

刷新页面后通过 `run_id` 恢复状态；浏览器本地存储不能作为正式推荐历史。

## 8. 可访问性与交互

- 推荐结果使用有序列表；每项标题为三级标题；
- 生成状态使用 `aria-live="polite"`，错误使用 `role="alert"`；
- 展开摘要按钮维护 `aria-expanded` 和 `aria-controls`；
- 推荐信号不能只依赖颜色，必须包含文字；
- 键盘顺序为研究选择、推荐目标、数量、生成、排序、逐条文献操作；
- 弹窗关闭后焦点返回触发按钮；
- 移动端触控目标至少44px；
- 仅使用120/220/360ms锁定动效，减少动效模式下移除位移。

## 9. 页面流

```text
进入文献推荐
  → 自动加载当前研究和最新结果快照
  → 选择推荐目标与数量
  → 创建Recommendation Run
  → 获取PubMed候选
  → 相关度筛选
  → 排除已有和近重复文献
  → 计算证据适配
  → 原子激活Run
  → 查看推荐依据
  → 加入候选或忽略
```

## 10. 第一版实施范围

必须实现：

- 当前研究和结果快照绑定；
- 三种推荐模式；
- 相关度、增量价值、证据适配三项评分；
- 当前结果、阅读计划、知识库的精确PMID/DOI去重；
- 标题摘要语义近重复判断；
- 结构化推荐理由；
- Recommendation Run持久化和历史；
- 候选池状态；
- 完整加载、空、部分成功、失败状态。

暂不增加复杂证据矩阵、聚类图、用户自定义权重、推荐订阅和自动定时任务。

## 11. 验收标准

- 用户无需重新输入研究问题即可生成推荐；
- 推荐结果不包含当前集合中的精确重复项；
- 每篇推荐都能展示三类结构化理由及数据来源；
- 任一评分输入缺失时不会伪装为0；
- 推荐失败不清空上一版可用结果；
- 加入候选后刷新页面状态仍然保留；
- 从“已在检索结果”可定位到对应PMID；
- 桌面、1024px和移动端没有内容遮挡或水平溢出；
- 页面全流程可使用键盘完成；
- 所有动态状态有屏幕阅读器通知；
- 不以商业期刊指标作为生成推荐的必要条件。

## 12. Build Handoff

- 目标工程实现：Vue 3 Composition API、`<script setup lang="ts">`，由熟悉当前项目的Vue工程代理执行。
- 设计系统：沿用项目现有语义组件和CSS token；复杂Select、Dialog、Dropdown采用已锁定的Reka UI原语，不手写仿制。
- 复用现有 Literature Search、Scoring Generation、OpenAlex、Reading Plan、知识库和重复检测服务。
- Implement exactly this spec. Theme the design system with our locked tokens; do NOT redesign or re-implement its components.

## 13. Pre-Flight

- Identity lock：通过，未新增颜色、字体、圆角或图标体系。
- Anti-slop：通过，无营销Hero、卡片墙、装饰性渐变和无意义状态。
- 状态覆盖：通过，覆盖无研究、无Intent、运行、部分成功、零新增、失败、离线。
- 可访问性：通过，定义焦点、键盘、ARIA、动态通知和移动端触控。
- 认知负担：通过，生成前仅三个决策，页面只有一个主操作。
- 自评：distinctiveness 3，hierarchy 4，consistency 4，accessibility 4，state coverage 4，copy 4，restraint 4，motion 4，总分31/32，无轴低于3。
