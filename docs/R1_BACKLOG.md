# R1 Backlog

本文件只记录 R1 候选工作，不在 R0-WP09 实施。优先级需在 R1 启动评审中确认。

## 准入后优先事项

- 设计安全、可迁移、支持多进程的 PaperQA 索引持久化；禁止直接信任外部 pickle。
- 生成包含全部传递依赖与哈希的 Windows/CI 锁文件，并定义升级机器人和回滚策略。
- 评估 `qwen3:4b` 思考文本分离、答案长度控制和更大本地模型质量基线。
- 建立精确页码/段落定位能力，并明确 PDF 页、印刷页和文本块页范围的语义。
- 将 PaperQA 适配器接入经过评审的业务 Service；Router 不直接调用外部 RAG。

## 工程质量

- 在独立提交中统一 28 个早期脚手架文件的 Ruff 格式。
- 评估 FastAPI/Starlette TestClient 到 `httpx2` 的迁移。
- 在 Windows CI 中执行默认 pytest、mypy、Ruff、Alembic check 和敏感文件检查。
- 为真实 integration 增加稳定性统计、超时预算、重试边界和成本上限。

## 安全与产品边界

- 在启用多用户或正式 API 前完成认证、授权、审计日志、密钥轮换和论文访问控制设计。
- 定义未发表论文的保留、删除、加密和脱敏政策。
- 明确云端发送文献内容前的用户确认、供应商许可和数据驻留要求。
- 在业务范围批准前不实施 PubMed、完整知识库、科研写作或 LangGraph Agent。
