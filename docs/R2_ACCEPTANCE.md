# R2 真实用户检索验收标准

状态：**待执行**。本文件是 R2-WP13《真实用户检索验收》的验收结论文档：每一条验收项来自 `docs/R2_USER_TEST_SCRIPT.md` 的 9 步固定任务与来源需求，验收证据必须来自真实试用记录（`docs/R2_USER_TEST_REPORT.md`）或可复现的代码/接口证据，不虚构。未满足项必须给出证据与原因，不得宣称通过。

## 验收项

### 1. 结果大部分相关

- **判定标准（必须同时满足）**：
  - `total_count > 0`（第 3 步执行检索真实返回非空结果）。
  - 用户对第 3 步「结果相关性主观打分（1–5）」给出 **≥ 4**。
  - 用户/观察者在报告中给出「明显无关结果占比」或「TOP N 中明显无关条数」等具体观察；仅写"相关"不构成证据。
- **证据要求**：第 3 步记录表（检索式、`total_count`、`searched_at`、主观打分、具体观察）；出现明显无关结果时列出典型 PMID 与判断依据。
- **验收方式**：审查 `R2_USER_TEST_REPORT.md` 第 3 步记录与相关性打分。

### 2. 检索式可理解

- **判定标准（必须同时满足）**：
  - 第 2 步生成的布尔检索式满足：同义词组以 `OR` 连接、概念组以 `AND` 连接、带字段标签（如 `[Title/Abstract]`）；不含纯中文词；由医学检索规范导出（布尔逻辑 + 字段限定）。
  - 用户对「检索式可读性打分（1–5）」给出 **≥ 3**，并能说出检索式对应的概念（如"疾病 AND 干预"）。
  - 观察记录中出现至少一个"检索式为何可理解/何处难懂"的具体现象。
- **证据要求**：第 2 步记录表（检索式原文、可读性打分、是否需人工修正词分组、MeSH 候选可用性、布尔逻辑是否可理解）。
- **验收方式**：审查 `R2_USER_TEST_REPORT.md` 第 2 步记录；必要时对照第 3 步 `search_string` 与第 1 步原始主题核对检索式确由系统生成而非硬编码。

**结论：** 待填（通过 / 不通过 / 部分，须附证据编号）

### 3. 去重基本准确

- **判定标准（必须同时满足）**：
  - 第 5 步生成的重复组数量与成员构成可解释：每个组标注匹配方法（PMID / DOI / 标题规范化 / 作者+年份）与置信度（clear / fuzzy）。
  - 用户对「去重准确性」给出判定，且报告记录了具体观察（重复组数、各匹配方法分布、置信度、采用动作、是否出现误判）。
  - **误判约束**：不得出现"明显非重复被判为重复"且未撤销的严重误判；所有解决操作可撤销（undo），撤销后原始检索结果不被删除或改写。
  - 已知边界：结果页直接跳转时前端以结果 ID 回退为任务 ID，若同一整数恰好也是某任务 ID，可能去重到错误任务；该场景不作为系统缺陷，但记录现象（见 `docs/R3_BACKLOG.md`）。
- **证据要求**：第 5 步记录表（重复组数、匹配方法分布、置信度、采用动作、误判现象）。
- **验收方式**：审查 `R2_USER_TEST_REPORT.md` 第 5 步记录；必要时用 `GET /api/v1/duplicate-groups` 抽查重复组成员与 `trigger_task_id`。

**结论：** 待填（通过 / 不通过 / 部分，须附证据编号）

### 4. 矩阵可用于实际工作

- **判定标准（必须同时满足）**：
  - 第 8 步比较矩阵（`POST /api/v1/comparisons` + `GET /comparisons/{id}`）生成成功，单元格带可追溯来源（真实 PMID/DOI + locator）或显式「缺失」标注；无来源值不得出现无凭据的生成值。
  - 第 9 步证据矩阵（`POST /api/v1/evidence-matrices` + 导出）生成成功，带版本号；Markdown / CSV 导出可在本地编辑器打开核对，中文与缺失值标注正确。
  - 用户对「矩阵可用于实际工作（1–5）」给出 **≥ 4**，并给出至少一个具体使用场景观察（如"用于写综述的证据表格"）。
  - 边界说明：比较矩阵的证据来自 `paper_analysis` + `library_item`；只有本地文档且已有结构化分析的收藏才有生成值，`metadata_only` 收藏对应单元格为「缺失」。这是当前真实能力边界，不因出现「缺失」单元格判不通过；但「缺失」单元格数必须记录。
- **证据要求**：第 8、9 步记录表（3 个文档 ID、有来源单元格数、「缺失」单元格数、人工修订是否保留、矩阵可用性打分、矩阵 ID/版本号、导出核对结果）。
- **验收方式**：审查 `R2_USER_TEST_REPORT.md` 第 8、9 步记录；抽查导出的 Markdown/CSV 内容与缺失值标注。
