# 单篇文档导入：必须归属知识库

## 1. 目标与边界

本设计解决“用户只想导入一篇文档”与“资料必须有清晰来源容器”之间的冲突。

目标：用户可以导入单篇文档，但每份文档在创建前必须明确归属到一个可见的知识库；系统不得再自动创建“上传文档”“临时文件”或“未知来源”等隐式知识库。

本设计仅定义后续实现方案，不删除现有文档、上传文件、上传接口或已有知识库记录。

## 2. 信息架构

```text
文档与知识
├─ 知识库：管理资料来源、文件夹和导入入口
│  └─ 导入资料
│     ├─ 导入资料文件夹
│     └─ 导入单篇文档
└─ 文档库：查看、解析、索引和使用具体文档
```

单篇导入后的归属必须始终可表达为：

```text
知识库 / 可选子目录 / 文件名
```

例如：`肿瘤免疫文献 / 2026 新文献 / PD-1 联合治疗.pdf`。

## 3. 入口与页面职责

### 3.1 知识库：唯一导入入口

知识库页面主按钮由“添加资料文件夹”调整为“导入资料”。点击后先让用户选择导入类型：

```text
导入资料
├─ 资料文件夹
│  └─ 选择本地文件夹，作为知识库来源后同步扫描
└─ 单篇文档
   └─ 选择单个文件，再选择归属知识库
```

“导入单篇文档”使用右侧抽屉或模态窗口完成；文档库页面不再提供上传入口。

### 3.2 文档库：只处理已归属文档

文档库继续负责文件列表、详情、预览、解析、索引、失败重试与 AI 资料导航。

文档库显示每篇文件的知识库名称与相对路径，但不负责选择文件、上传文件或新建知识库。

## 4. 单篇文档导入交互

导入流程分为三个连续步骤；没有归属时不能提交。

```text
步骤 1：选择文件
  → 步骤 2：选择归属
  → 步骤 3：确认并导入
  → 导入成功：跳转到对应知识库范围的文档库
```

### 4.1 步骤 1：选择文件

- 支持一次选择一篇文件。
- 前端显示真实文件名、大小和识别出的格式。
- 仅允许后端已支持的格式；不因为前端显示了文件就假定它可解析或可预览。
- 文件选择错误、格式不支持、超出大小限制时，在本步骤给出明确错误，不进入上传。

### 4.2 步骤 2：选择归属

归属是必填项，提供两个互斥选项：

1. **放入已有知识库**
   - 下拉列出当前可用知识库。
   - 默认不预选，避免把文件误放进上一次使用的知识库。
   - 被选择的知识库应显示名称、路径和当前文件数量。

2. **新建知识库后放入**
   - 用户填写知识库名称，例如“待整理文献”或“课题 A 补充资料”。
   - 系统创建一个用户可见、可管理的知识库记录，再导入文件。
   - 名称必填且需检查重复；若失败，不上传文件或不创建孤立记录。

可选字段：`子目录`。它用于逻辑归档，例如“2026 新文献”；为空时文件位于知识库根目录。该字段必须经过路径安全校验，禁止 `..`、绝对路径和盘符。

### 4.3 步骤 3：确认并导入

确认区必须展示用户即将得到的真实归属预览：

```text
文件：PD-1 联合治疗.pdf
归属：肿瘤免疫文献 / 2026 新文献
导入后：等待解析；解析成功后可建立索引并用于本地 RAG。
```

- 用户未选文件或未选归属时，“开始导入”按钮禁用。
- 提交期间禁用重复点击，并显示上传/校验进度。
- 成功后只显示真实返回状态；不能声称已解析或已建立索引。
- 成功后跳转至：`/documents?sourceId=<knowledge_source_id>`。

## 5. 后端数据与接口契约

### 5.1 不再允许隐式来源

现有直接上传逻辑会自动创建名称为“上传文档”的临时知识库。下一阶段实现时必须移除该行为。

上传请求必须提供以下二选一归属信息：

```text
已有知识库：knowledge_source_id
或
新建知识库：new_knowledge_source.name（以及可选的受控存储配置）
```

若两者都缺失、同时提供，或目标知识库不存在/不可用，接口返回可理解的 4xx 错误，且不得保存文件、创建 Document 或创建 KnowledgeSource。

### 5.2 建议请求契约

建议保留独立导入接口，而不是让文档库调用通用上传接口：

```text
POST /api/v1/knowledge-sources/import-document
Content-Type: multipart/form-data

file: <单一文件>
knowledge_source_id: <可选，已有知识库>
new_source_name: <可选，新建知识库名称>
relative_directory: <可选，相对目录>
```

约束：

- `knowledge_source_id` 与 `new_source_name` 必须且只能提供一个。
- `relative_directory` 仅接受安全的相对路径。
- 响应应返回真实的 `knowledge_source`、`document`、`asset` 与后续解析入口；不要自动伪造解析或索引完成。
- 文件保存必须位于该知识库对应的受控存储范围中；Document 保存相对路径、原始文件名、哈希、大小、格式和处理状态。

### 5.3 事务与失败处理

- 先验证请求、文件与目标归属，再写入持久文件。
- 写入失败或数据库创建失败时，清理临时文件与已写入的目标文件。
- 新建知识库与创建文档必须保持原子性：任一步失败都不能留下孤立的知识库或 Document。
- 不删除用户已有来源，也不迁移已有“上传文档”来源中的数据；该历史数据的整理必须另行设计并取得用户确认。

## 6. 处理状态与后续操作

成功导入后，文档初始状态只能是实际状态，例如：

```text
导入成功 → 等待解析 → 解析成功/失败 → 等待索引或索引过期 → 索引成功/失败
```

- 是否自动触发解析，应作为实现时明确的产品决定；若自动触发，界面必须显示“正在解析”，而不是“已完成”。
- 索引只允许在解析成功后进行。
- PPTX、DOCX 等“可解析但不可在线预览”的格式，需分别显示解析能力与预览能力，不能混为“不可用”。

## 7. 异常提示

| 情况 | 用户提示与处理 |
|---|---|
| 未选择归属 | 禁用提交，提示“请选择资料归属”。 |
| 目标知识库不存在或已停用 | 提示选择其他知识库；不上传。 |
| 新知识库名称重复 | 提示修改名称或选择已有知识库；不上传。 |
| 格式不支持 | 提示真实支持范围；不创建记录。 |
| 文件校验/写入失败 | 显示可理解错误；清理临时文件。 |
| 解析失败 | 文件仍保留在已选知识库，文档库展示失败原因与重试操作。 |

## 8. 验收标准

实现完成后必须满足：

1. 文档库页面没有任何直接上传入口。
2. 知识库页面可选择“导入资料文件夹”或“导入单篇文档”。
3. 导入单篇文档时，未选已有知识库、也未填写新知识库名称时不能提交。
4. 用户选择已有知识库后，导入结果的 `Document.knowledge_source_id` 与选择一致。
5. 用户选择新建知识库后，新知识库在知识库列表中可见，且导入文档明确归属它。
6. 系统不会自动创建“上传文档”“临时文件”“未知来源”等名称的知识库。
7. 导入失败不会留下孤立文件、孤立文档或孤立知识库。
8. 导入成功后跳转到该知识库限定范围的文档库，并展示真实处理状态。
9. 新增后端与前端测试覆盖已有知识库、新建知识库、缺失归属、非法路径、失败回滚和成功跳转。

## 9. 非本阶段内容

- 不删除、迁移或重命名既有“上传文档”知识源。
- 不实现文件夹树与子目录树的完整可视化；本设计仅预留安全的逻辑子目录字段。
- 不承诺所有格式均可解析、索引或预览。
- 不改变 RAG 只基于已解析且已索引的真实本地文档进行检索的边界。
