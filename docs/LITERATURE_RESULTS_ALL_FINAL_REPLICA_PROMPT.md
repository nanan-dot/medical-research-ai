## 3. 页面定位与业务边界

这是一次 PubMed 检索结果快照的“全部文献”集合页，不是单篇论文详情页，也不是论文研究工作区。

页面帮助用户完成四件事：

1. 看清当前检索任务和真实结果范围。
2. 依据研究类型、相关性、文章级指标和期刊指标判断优先阅读顺序。
3. 筛选、排序、保存、标记阅读状态、去重和访问合法全文来源。
4. 导出当前真实结果的文献元数据/引用数据。

页面不得收集出版社账号、密码、Cookie 或机构登录信息；不得绕过付费墙；不得伪装成自动下载付费全文。

## 5. 页面结构

### 5.1 Research Context 顶部

使用紧凑结构：

- 面包屑：`文献检索 / 检索结果 / 全部文献`。
- 研究主题作为 H1；来自真实任务 `original_query`，失败时诚实回退为“本次检索结果”。
- 轻量阶段轨迹：研究问题 → 检索意图 → 策略构建 → 结果。结果节点显示真实数量。
- 元信息：PubMed、策略版本（真实存在才显示）、检索时间（真实存在才显示）。
- 区分并清晰标注：`PubMed 命中总数`、`本地快照/当前加载数量`、`当前筛选结果数`。不要把接口已加载条数冒充 PubMed 总命中数。
- 显示系统的近 15 年检索边界，但只在真实任务/接口能够证明时显示。
- 右上保留“查看检索策略”“重新检索”；复用既有路由/行为，没有真实行为则不制作假按钮。

### 5.2 Tab

顺序固定：

- 全部文献 + 真实计数
- 已保存 + 真实计数（没有独立计数接口时不得假造，可省略数字）
- 重复文献 + 真实待处理数量（不可得则省略）

当前项使用蓝字和 2px 下划线；不要做成大胶囊按钮。URL query 保持刷新、前进和后退一致。

### 5.3 排序与筛选工具条

首行排序入口按真实 `sort_capabilities` 呈现：

- 综合推荐/综合相关性
- 相关性
- 近期热度
- 最新发表
- 文章影响力
- 经典度
- 更多

“热门”统一命名为“近期热度”，避免与论文长期影响力混淆。没有真实文章级数据或后端声明不可用时，禁用并给出简短原因，或不展示；不得前端计算假分数。

已应用筛选 Chip 最多显式显示 4 个，其余折叠为 `+N 条`；支持逐项删除和清除全部。筛选、排序和页码继续同步 URL。

右侧工具区保留：

- 筛选条件（小屏打开 Drawer，桌面控制侧栏）
- 导出
- 阅读密度/紧凑密度切换（仅视觉密度，不得再次引入阅读计划概念）

### 5.4 导出设计（必须实现真实闭环）

按钮名称保持“导出”。点击打开键盘可操作的菜单或 Popover，明确说明：`导出文献数据，不包含 PDF 全文`。

格式只提供后端已支持且已核实的：

- CSV：便于表格整理。
- RIS：适合 Zotero、EndNote 等文献管理器。
- BibTeX：适合 LaTeX 引用管理。

当前代码的真实接口为 `/api/v1/literature-search/{id}/results/export`，格式为 `csv | ris | bibtex`，并带当前查询筛选参数。复用 `literatureSearchApi.exportResults`，不要另造平行接口。

导出范围必须与后端真实行为一致：默认描述为“当前筛选结果”。不要声称可导出“已勾选”“仅当前页”或“全部 PubMed 命中”，除非代码审计后补齐对应后端语义、行为测试和边界保护。勾选文献时，若后端仍不支持按 PMID 导出，菜单仍诚实标注“当前筛选结果”，不得让用户误会只导出选中项。

导出过程：按钮 loading、防重复提交；成功触发浏览器下载；服务端文件名可用时优先使用 `Content-Disposition`，否则使用包含结果 ID、日期、格式的安全文件名；失败用可恢复错误提示；结束后释放 Object URL。不得导出 PDF、账号信息、Cookie、未进入本地结果快照的数据或前端拼出的假字段。

### 5.5 三栏结果工作区

桌面端：沿用全局导航约 190–210px；中央内容 `flex: 1` 且是最大区域；右侧筛选约 260–290px。页面整体应尽量利用横向宽度，不把结果压成窄列。

1200–1439px 缩窄右栏；900–1199px 隐藏右栏并通过 Drawer 打开；小于 900px 按现有移动导航，卡片纵向排列。避免横向滚动。

## 6. 文献卡片

默认结构：

1. Checkbox 和当前页连续序号。
2. 可点击标题，最多 2 行。
3. 作者、期刊、年份、PMID 等紧凑元信息；字段缺失时省略，不拼出多余分隔符。
4. 第一层最多 4 个高价值标签：研究类型、JCR Q 区、IF、近期热度。其余信息进入详情/悬浮层。

7. 右侧状态和轻量操作：保存、已读/在读/重点、访问 PubMed/合法全文、更多菜单。

### 6.1 严格区分三类数据

- 相关度/证据匹配：论文与当前研究问题的匹配程度，不代表论文质量。
- 文章级指标：近期热度、文章影响力、经典度、被引数，来自真实 `score_summary`/OpenAlex 数据。
- 期刊级指标：IF、JCR、WoS 收录、中科院分区，来自已激活期刊指标批次。

不得混用概念，不能用 IF 推导文章热度，不能用相关度表示可信度。

### 6.2 期刊指标

按真实匹配结果展示：

- `IF 数值 + IF 年份`
- `JCR Q1–Q4 + 年份`
- `SCIE / SSCI / ESCI / AHCI` 精确收录类别
- `中科院 1–4 区 + 年份`

ISSN/eISSN/ISSN-L 优先、期刊名称备用的匹配逻辑属于后端，不得在前端重新匹配。未配置、未匹配、数据缺失必须分别诚实降级。只有真实十年详情接口已经存在时，才以懒加载 Drawer/Popover 提供最近十年记录；列表首屏只显示当前选定年份的紧凑标签。

### 6.3 全文与外链

- 任意合法 PMID：`访问 PubMed ↗`，新标签页并使用 `rel="noopener noreferrer"`。
- PMCID 存在且本地全文尚不存在：可显示 `获取 PMC 开放全文`；只在用户点击后调用现有后端完成官方许可核验和获取。
- DOI 存在：可显示 `登录后获取全文 ↗`，仅跳转 DOI/出版社外部页，用户在浏览器自行登录；系统不保存账号。
- 本地全文已经存在：显示 `打开本地全文`，进入现有文档/论文研究流程。
- 页面加载不得自动请求全文或下载文件。

更多菜单应保持精简，只包含真实可用动作，例如保存/取消保存、标记已读/未读、重点、访问 PubMed、复制 PMID/DOI、合法全文入口。不要出现知识库和本地 PDF 导入。
