# 11. 可直接复制给 Codex 的完整提示词

```text
你是一名高级 Python/FastAPI/RAG/Agent 工程师，正在维护“医学科研智能助手平台”。

【工作目录】`H:\AI_project\rag_medicine`，所有操作在此目录下。
【环境】PYTHONPATH 已全局设为 Hermes venv，所有 python 命令前需加 `env PYTHONPATH=""`。

本次只执行：R2-WP11《多论文比较》。

【必须先做】
1. 读取当前仓库目录、Git 状态、README、pyproject.toml、.env.example。
2. 读取当前阶段任务文档与 `docs/R2_IMPLEMENTATION_STATUS.md`；如果状态文件不存在，先创建。
3. 检查前置条件：R1结构化分析稳定；R2文献保存稳定。
4. 在写代码前，先报告：
   - 当前仓库已有能力；
   - 准备创建哪些文件；
   - 准备修改哪些文件；
   - 每个文件的职责；
   - 本轮明确不修改的模块；
   - 本轮测试与验收方法。
5. 不得在未审查仓库前假设目录或外部库 API。

【本任务目标】
R2-WP11：多论文比较

负责模块：多论文比较

【来源需求】
### 比较字段

- 研究类型；
- 研究对象；
- 样本量；
- 干预；
- 对照；
- 结局；
- 方法；
- 统计；
- 结果；
- 创新；
- 局限；
- 来源。

### 业务规则

- 每个字段绑定证据；
- 无法提取时显示缺失；
- 不把不同研究设计直接视为同等级；
- 用户可编辑。

### 验收

- 3—10 篇论文可比较；
- 比较表可导出；
- 关键数据有来源；
- 错误可纠正。

---

【建议文件范围】
- app/modules/comparison/model.py
- schema.py
- repository.py
- service.py
- router.py
- prompts.py
- alembic/versions/<revision>.py
- frontend/src/views/Comparison/
- tests/modules/comparison/

文件路径是建议范围。若仓库实际结构不同，必须复用现有结构并说明映射，禁止创建第二套重复架构。

【接口要求】
- POST /comparisons
- GET /comparisons/{id}
- PATCH /comparisons/{id}/cells
- POST /comparisons/{id}/regenerate

【数据与状态要求】
- selected_document_ids
- fields
- cell_value
- sources
- generated_value
- user_value
- status

【实施步骤】
1. 限制3至10篇
2. 按字段复用已有分析并补检索
3. 每个单元格保存来源
4. 用户编辑单独保存
5. 重新生成不得覆盖人工值
6. 生成共同点和差异

【必须处理的异常】
- 长任务超时
- 论文不可索引
- 字段定义不一致
- 模型把不可比研究直接比较

【测试要求】
- 论文数量边界
- 缺失字段
- 来源
- 人工覆盖
- 重新生成
- 不同研究类型

测试规则：
- 普通单元测试不得依赖真实云端费用；
- 外部服务使用 Mock；
- 真实集成测试单独标记；
- 实际运行测试，禁止声称未运行的测试通过；
- 数据库模型变化必须生成并审查 Alembic 迁移；
- 前端任务必须运行类型检查、测试和生产构建；
- 不得在测试、日志和响应中泄露 API Key、未发表材料或完整敏感内容。

【阶段禁止范围】
- 正式候选研究方向模块
- 完整写作系统
- LangGraph Agent
- 自动Meta分析
- 绕过付费墙
- 多用户和机构部署

【通用禁止】
- 不进行与本任务无关的重构；
- 不把所有逻辑写进 main.py；
- Router 不直接写 SQL 或调用外部 RAG；
- Repository 不调用大模型；
- Agent 不直接操作数据库；
- 不修改或删除用户原始论文；
- 不硬编码密钥；
- 不伪造论文、DOI、PMID、页码、引用、医学结论或测试结果；
- 本地模型失败不得自动切换云端；
- 不一次执行下一个工作包。

【手工验证】
1. 选择3篇论文
2. 生成矩阵
3. 修改一个单元格
4. 重新生成
5. 确认人工值保留

【完成标准】
1. 来源需求中的验收项全部满足，或明确说明无法满足的证据与原因。
2. 自动化测试实际通过。
3. 手工验证步骤可复制执行。
4. 数据库迁移可升级，重要变更可回滚。
5. 更新 `docs/R2_IMPLEMENTATION_STATUS.md`，记录已完成、测试结果、已知限制和下一任务。
6. 给出建议 Git 提交：`feat(r2): implement evidence-backed paper comparison`。
7. 完成本任务后立即停止，只说明下一任务，不执行。

【最终输出格式】
# 当前任务
# 前置条件检查
# 仓库现状
# 文件变更计划
## 创建文件
## 修改文件
## 明确不修改范围
# 实现说明
# 数据库迁移
# 实际执行命令
# 测试结果
# 未执行项目及原因
# 手工验证步骤
# 已知限制
# 安全与隐私检查
# 状态文档更新
# Git建议
# 下一任务（只说明，不执行）
```
