【本任务目标】
R2-WP04：检索任务与历史——保存可复现的检索过程。

【来源需求】
### 目标
保存可复现的检索过程。

### 记录（每项都要持久化）
- 原始自然语言主题（original_query）；
- 结构化条件（structured_query）；
- 检索式（search_string）；
- 检索日期（searched_at）；
- 数据库（database）；
- 结果数（result_count）；
- 筛选条件（filters）；
- 模型（model_version）；
- 用户修改（user_edits）。

### 验收
- 用户可重新运行；
- 检索式和日期可导出；
- 相同任务可复现；
- 结果变化有提示。

【与 WP03.5 的衔接（必须遵守）】
- WP03.5 已有 `LiteratureSearchResult`（检索执行结果落库，含 items_json + verified 标记）与
  `execute` / `{id}/results` / `{id}/bibtex` 端点。WP04 的"任务"层应**包装/关联**这些已有成果：
  - 新增"检索任务"（literature search task）实体：原始主题、结构化条件、数据库、模型、
    筛选、用户修改、状态机（pending/running/succeeded/failed）；
  - 任务与 `LiteratureSearchResult` 关联（任务保存的是**结果引用**而非无限复制 items_json）；
  - 重跑（rerun）复用 `pubmed_executor` / `execute_search` 逻辑，创建**新版本**结果，不覆盖旧结果；
  - 结果变化提示：重跑后对比新旧 result_count / items，输出变化摘要（新增/减少条目数）。
- 禁止：重建一套平行的"检索执行"逻辑；禁止复制 items_json 到任务表造成数据膨胀（
  处理"历史记录过大"异常）。

【接口要求】
- POST /literature-search（创建检索任务）
- GET /literature-search（历史列表，分页）
- GET /literature-search/{id}（任务详情，含关联结果）
- POST /literature-search/{id}/rerun（重跑，创建新版本）

【数据与状态要求】
- original_query
- structured_query
- search_string
- searched_at
- result_count
- filters
- model_version
- status（任务状态机：pending → running → succeeded / failed）
- 版本关联：task 关联多个 result 版本，rerun 产生新版本

【实施步骤】
1. 持久化完整检索输入（任务实体）；
2. 执行任务状态机；
3. 保存结果引用而非无限复制（关联 LiteratureSearchResult，不复制 items_json）；
4. 支持重跑并创建新版本；
5. 显示结果变化（新旧版本对比摘要）；
6. 导出策略（复用 WP03.5 的 bibtex 导出 + 检索策略导出：查询串、日期、数据库、结果数）。

【必须处理的异常】
- 历史记录过大（引用而非复制；分页加载）；
- 重跑覆盖旧结果（新版本，不覆盖）；
- 时间区间变化（记录每次 searched_at，导出含日期）；
- 模型版本不可追踪（记录 model_version，来源真实配置）。
