在仓库 `H:\AI_project\rag_medicine` 中补全「文档与知识」页面的两块后端能力，供前端知识库卡片展示真实聚合统计、以及"查看文档"跳转后按来源限定文档列表：

## 2. 聚合统计字段定义（必须与设计说明一致）

对每个知识源（按 `documents.knowledge_source_id` 分组统计）：

| 字段 | 含义 | SQL 条件 |
|---|---|---|
| `total_files` | 文件总数 | `COUNT(*)` |
| `parsed` | 已解析成功 | `parse_status = 'succeeded'` |
| `indexed` | 已建立索引 | `index_status = 'succeeded'` |
| `pending` | 待处理（尚未解析成功且未失败） | `parse_status IN ('pending','parsing')` |
| `failed` | 异常（解析失败或索引失败） | `parse_status = 'failed' OR index_status = 'failed'` |

补充约束：

- `total_files` 恒等于 `parsed + pending + failed` 不强制成立（文档可能解析成功但尚未建立索引），字段含义以表格为准，不做人为凑数。
- 统计基于 `documents` 表的**实时查询**（`COUNT` + `CASE WHEN` 聚合），不做缓存、不加新表、不加迁移（若现有表结构已足够）。
- 若现有 `scan_state` 语义与上述条件冲突（如 `outdated` 应计入哪一类），按代码中真实语义归类并写中文注释说明理由。

## 3. API 变更

### 3.1 列表带统计

`GET /api/v1/knowledge-sources` 响应模型 `KnowledgeSourceRead` 增加字段：

```python
class KnowledgeSourceStats(BaseModel):
    total_files: int = 0
    parsed: int = 0
    indexed: int = 0
    pending: int = 0
    failed: int = 0

class KnowledgeSourceRead(BaseModel):
    # ...现有字段不变...
    stats: KnowledgeSourceStats
```

列表查询在 `service.list()` 中对每个知识源执行一次文档统计查询（或一次性 `GROUP BY knowledge_source_id` 聚合后映射，优先后者，避免 N+1）。

### 3.2 单源统计端点

`GET /api/v1/knowledge-sources/{id}/stats`，响应 `KnowledgeSourceStats`。知识源不存在时返回现有 `NotFoundError` 语义。

### 3.3 文档按来源过滤

`GET /api/v1/documents` 增加可选参数 `knowledge_source_id: int | None = None`，透传到 `DocumentService.list()` 与 `DocumentRepository` 的查询条件（`WHERE knowledge_source_id = :id`）。现有行为（不传时返回全部）保持不变。
