【本任务目标】
R2-WP05：筛选、排序与分页。

【来源需求】
### 筛选
- 年份；
- 文献类型；
- 期刊；
- 作者；
- 是否有摘要；
- 是否已保存；
- 是否已读；
- 标签。

### 排序
- 相关性；
- 最新；
- 经典代表性；
- 用户自定义。

### 验收
- 大结果集可分页；
- 筛选不会丢失状态；
- 排序理由可解释。

【与 skills 的融合点（必须体现）】
1. **"经典代表性"排序**（search-lit 融合）：代表性 = 被引量/权威性信号。因当前数据源
   （PubMed ESearch）不返回被引量，采用**可解释的替代信号**并在响应中说明：
   期刊权威性（如 Nature/JAMA/NEJM 等 top 期刊加权）、年份权重、verified 标记。
   设计决策必须写入中文注释并输出"排序理由"字段（见下），禁止编造被引量数字。
2. **"排序理由可解释"**（search-lit 反幻觉协议延伸）：每个排序结果返回
   `sort_reason` 字段（如 "top journal + recent year" / "verified by pubmed"），
   前端可展示，绝不输出虚构的被引次数或影响因子。
3. **"已保存/已读/标签"**（manage-refs 融合）：这三项属于用户态数据，当前
   `items_json` 是快照（不可写回）。设计方案二选一并说明理由：
   a) 在 `literature_search_results` 旁新增用户态表（result_id + saved/read_status/tags），
      通过 GET 时 join 返回；或
   b) 独立模块 `app/modules/literature_search/user_state.py` 管理（推荐，避免污染快照表）。
   标签、已读、已保存的读写端点保持最小暴露。

【建议文件范围】
- app/modules/literature_search/filtering.py（白名单筛选参数 + 过滤逻辑）
- ranking.py（相关性/最新/经典代表性/自定义排序 + sort_reason）
- repository.py（分页查询扩展）

【接口要求】
- GET /literature-search/{id}/results?year=&publication_type=&journal=&author=&has_abstract=&saved=&read_status=&tags=&sort=&page=&page_size=
- （按你的方案）用户态读写：PUT/DELETE saved、read_status、tags 的最小端点。

【数据与状态要求】
- 筛选白名单：year / publication_type / journal / author / has_abstract / saved / read_status / tags
- 排序枚举：relevance / newest / classic / custom
- 分页：page（1-based）/ page_size（默认 20，上限 100）
- 响应含：items、total、page、page_size、sort、sort_reasons（列表，逐条解释排序理由）
- 筛选状态保留到 URL（前端 query 同步，刷新不丢失）

【实施步骤】
1. 定义白名单筛选参数（拒绝未知参数，非法值返回 422 而非静默忽略）；
2. 数据库侧分页（避免前端一次加载全部；items_json 快照在服务端分页切片，不整份下发）；
3. 相关性与时间排序（相关性 = PubMed 返回顺序即天然相关性；最新 = year 降序；
   经典 = 期刊权威性 + verified；自定义 = 用户态排序字段）；
4. 保留筛选状态到 URL（前端 router query 双向同步）；
5. 解释排序规则（sort_reason 逐条输出）；
6. 避免前端一次加载全部（分页加载 + 前端组件分页）。

【必须处理的异常】
- 相关性分数不可跨检索比较（sort_reason 说明"相关性为本次检索内排序"）；
- 期刊名称不统一（标准化小写比较 + 权威期刊白名单常量）；
- 年份缺失（year=None 排到最后，sort_reason 标注 "year unknown"）；
- 大结果性能（服务端分页切片，避免整份 items_json 下发）。
