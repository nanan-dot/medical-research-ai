## 产品边界与真实数据规则

### 局部导航

论文研究稳定局部 Tab 只能是：

```text
研究概览 | 单篇精读 | 证据问答
```

- `证据问答` 激活时，在 `/analysis` 内展示本工作台；不要跳到一个视觉脱节的普通聊天页面。
- 不新增第四个 Tab；禁止「笔记与标注」「阅读批注」成为 Tab。
- 原文批注仍属于单篇精读/文档工作区，本轮不实现。

### LIVE 数据约束

- 当前论文标题/状态：只能来自当前已选 `DocumentRecord` 的真实字段；未提供时显示克制的“未提供”，不得造数据。
- 会话历史：只能来自 `conversationsApi.list()` 返回的真实 `ConversationSummary`。可以筛选当前 `documentId` 命中的会话；不匹配时显示真实空状态。
- 当前会话：优先通过 `conversationsApi.latest(documentId)` 恢复；不存在时明确提示“尚无与当前论文关联的问答会话”，并提供真实的“创建问答会话”操作。
- 创建会话：仅在当前论文满足现有 `canAnalyze`/研究就绪条件时，调用 `conversationsApi.create([document.id])`。不可创建时给出由真实状态推导的禁用说明，不假装成功。
- 问答：调用现有 `conversationsApi.ask(conversation.id, question)`，加载中禁用重复发送，并呈现返回的 `answer_status`、`uncertainty`、`reason_codes`（仅在字段确实存在时）。
- 引用/来源：只能来自当前 assistant message 的 `citations`：`citation_text`、`evidence_text`、`page`、`section`。缺失字段显示“未提供”，而不是虚构页码、章节、论文标题或段落。
- 证据不足时必须明确表达系统不能把推断当论文事实；不能伪装为“已核实”。
- `conversationsApi` 或文档/会话请求失败时，显示可理解、可重试的错误，而不是退回 Mock 成功界面。

## 目标界面与交互

### 1. 页面头与论文上下文

保留当前 `/analysis` 的 `h1`、说明和局部 3 Tab。

证据问答激活时，在 Tab 下添加紧凑的“当前论文”上下文条：

- 显示真实当前文档标题（长标题换行/截断安全）；
- 显示真实解析/索引状态；
- 只在现有已选论文为空时显示指导性空状态；
- 提供“更换论文”或“返回研究概览”的明确链接/按钮，使用现有路由状态；
- 不展示裸 `documentId` 作为用户主信息。

### 2. 1440px 桌面工作台

在保留全局应用外壳的前提下，局部内容采用约 **21% / 54% / 25%** 的左中右结构；工作台必须优先利用可视高度，避免把少量内容堆在上方而在下方留下大面积无意义空白。

**左栏：当前论文范围与问题历史**

- 标题“当前论文范围”；体现本次问答只在当前论文范围内；
- 使用真实的当前论文/会话状态。若 API 没有“关联来源数”等聚合字段，不得造数字；可显示真实消息数或“由当前会话返回的引用数”，仅在可从响应确定时显示；
- 列出当前论文关联的真实会话历史，或明确、行动导向的空状态；
- 当前会话需要有清晰的激活态；
- 不变成文件平铺列表或统计卡片墙。

**中栏：待核对的论文式回答**

- 这是页面最重要的区域，禁止普通聊天气泡堆叠。
- 当前问题与回答分层：问题是较低强调的信息块；assistant 答案是阅读优先的主体。
- 回答区必须将其表达为**需要回源核对的证据摘要**，不是权威结论：
  - `answered` 时基于真实 citation 数量显示“已关联 N 个来源”；
  - `insufficient_evidence` 时明显显示“证据不足 / 需人工核对”；
  - 没有 citations 的回答明确标记“无可定位来源”；
  - `uncertainty`/`reason_codes` 仅在真实字段存在时以辅助状态展示；
  - 不自行生成“已核实”“待核对”等与真实返回不一致的状态。
- 回答下只提供真实有意义的动作：打开所选来源、引用反馈（复用现有 `feedback` 能力）等；不得添加 no-op 按钮。
- 输入区标题为“基于当前论文提问”，说明作用范围；拥有显式 label、键盘可用性、发送加载态以及当前文档/会话未就绪时的正确禁用/引导。

**右栏：来源与可追溯性**

- 点击中栏回答引用后，在此显示选中的真实 citation；也可按当前 assistant answer 列出真实 citations。
- 每条真实来源卡片仅呈现 API 确实提供的：引用文本（如果有）、`section`、`page`、`evidence_text` 与检索/证据状态。
- 页码/章节为空时显示“未提供”；不能合成演示锚点。
- “定位原文”只能在项目已有真正可用的定位/预览能力可以复用时出现；否则显示明确的 UNAVAILABLE 说明或不要渲染为可点击动作。严禁 no-op。
- 右栏必须有真实无引用/未选择引用状态，而非空白卡片。

### 3. 视觉质量

- 维持项目 Light Research Workspace token，不能往单个组件塞硬编码色值。
- 冷白/浅雾蓝画布、白色实体工作面、深海军蓝文字、学术蓝为唯一主强调，成功/警告仅为语义状态。
- 不能采用紫色渐变、霓虹、玻璃拟态、厚重阴影、圆角大卡片墙、营销 hero 或泛聊天产品视觉。
- 强化层级：页面标题 28–32px；工作区/模块标题 18–20px；正文 14–15px；元数据 12–13px。保持可读行高与足够对比度。
- 可使用细蓝色证据轨道表达“当前选择/证据引用/待处理”，不能仅作装饰。
- 避免 `transition: all`，只允许克制的 opacity/transform 150–220ms，并遵守既有 reduced-motion 规则。

### 4. 响应式与无障碍

- ≥1440px：左中右 21/54/25 工作台；
- 1024–1279px：中央保持阅读优先，来源区下移或抽屉，不挤坏阅读区；
- <1024px：单列；Tab 横向滚动；来源以按需可见的内容区呈现；
- 原生 `button`，可见 `:focus-visible`；
- 输入有 `label` 或明确 `aria-label`；
- 加载/错误/异步会话状态使用合适 `aria-live` / `role=status` / `role=alert`；
- 不依赖颜色作为唯一状态表达。

## 工程约束

- Vue 3 Composition API + TypeScript；禁止隐式 `any`。
- 一个文件一个职责；View 只做组装，API/会话状态放 composable，展示放专属组件。
- 对复杂状态的中文注释解释“为什么”：例如 documentId 切换时如何避免旧会话串入当前论文；不要写行为复述型注释。
- 先复用现有 `EvidencePanel` / `EvidenceItem` 或说明为什么论文研究需要专属呈现；不要复制一个职责相同、数据形状相同的组件。
- 所有新增/调整操作必须真实调用已有能力，或清楚标作 UNAVAILABLE；不写占位按钮。
- 保持单篇精读和 `/chat` 的既有 LIVE 功能；本轮不重做研究概览。

## 测试要求

为新行为补齐 Vitest 覆盖。最少覆盖：

1. 有 `documentId` 时使用真实当前文档与 `conversationsApi.latest` 恢复该论文会话；
2. 无会话时出现创建会话的真实引导，且不渲染演示论文/伪造引用；

6. 发送问题调用真实会话 API，并在 pending 时防止重复提交；
7. 现有研究概览和单篇精读 URL 状态恢复语义不回归。
