## 视觉与交互设计（必须落实）

### 设计定位

这是冷静、高信任、中高信息密度的医学科研工作区，参考 Nature / PubMed 的可读性与证据感。
它不是后台仪表盘、网盘、营销页或泛 AI 聊天页。

### 必须解决的旧页面问题

旧页面的标题、Tab、论文上下文条、分析卡和证据栏同时竞争视觉重心；默认进入三栏报告也没有告诉用户“下一步该做什么”。
新首屏必须建立清晰的任务流：

```text
选择或继续一篇已索引论文
→ 进入单篇精读 / 证据问答
→ 处理待人工确认事项
```

### 桌面布局（1440px）

在保留现有全局侧栏与顶部栏的前提下：

1. 页面页头：
   - 一个 `h1`：`论文研究`；
   - 简短说明：`读懂、核对并沉淀一篇或一组论文的证据。`；
   - 标题下为局部 Tab：`研究概览 | 单篇精读 | 证据问答`；当前项用学术蓝文字 + 2px 底边，禁止肥大胶囊。

2. 首要区域：`继续你的论文研究`。
   - 左侧为主区（约 60%）：可搜索的**已索引论文选择器**。搜索/列表用标题或文件名；选择结果包含真实可用的状态信息。
   - 选择论文后，主行动是清晰的 `开始单篇精读`；如果论文上下文已经可恢复，使用 `继续单篇精读`。
   - 不使用手动 ID 输入；不把大面积空白、统计数字或功能卡堆作为主体。

3. 同一首屏右侧（约 40%，但不是永久空白“证据栏”）：`待人工确认`。
   - 只显示 overview API 实际返回的待确认项；每项要有论文名称、字段/状态和可理解的下一步。
   - 空数组时，显示克制的行动导向空状态，不造假数量或样例医学论文。

4. 首要区域下方：
   - `最近精读` 与 `最近证据问答` 是纵向研究流，而不是三到六张均等卡片；
   - 每条只呈现真实已提供的标题、最近动作/时间、明确动词（如“继续精读”“恢复会话”）；
   - 空时显示行动导向空状态，不填充虚构论文。

5. 不在概览页保留旧版的：结构化报告、分析目录、右侧来源卡片墙、孤立的“进入单篇问答”按钮。

### 视觉令牌与细节

- 画布：`#FAFCFF` 或极浅雾蓝；白色实体内容面；
- 主文字：`#142033`；唯一主强调色：`#245DD6`；
- 已核实成功才用 `#198A62`；待确认/数据不足才用 `#B86A12`；
- 禁止紫色渐变、玻璃拟态、霓虹、夸张阴影、圆角卡片墙；
- 页面标题 28–32px，模块标题 18–20px，正文 14–15px，元数据 12–13px；
- 使用项目现有的语义 CSS token，不能在组件内散落无语义色值；如果需要缺失 token，先检查现有 token 定义并最小化复用；
- 唯一可辨识细节是“证据轨道”：待确认项、来源/状态关联处可使用细蓝色左轨，但它必须表达来源或待处理关系，而非装饰；
- 仅 `opacity`/`transform` 过渡，150–220ms；不得 `transition: all`；尊重 `prefers-reduced-motion`。

### 响应式与无障碍

- ≥1440px：研究起点为 60/40 双区；
- 1024–1279px：保持中央优先，右区在内容下方或抽屉，不挤压选择器；
- <1024px：单列；Tab 可横滚；
- 所有按钮用原生 `<button>`，具有可见 `:focus-visible`；
- 输入具 `<label>`/`aria-label`；异步加载/错误使用合适的 `aria-live` 或 `role=status/alert`；
- 长论文标题必须截断/换行安全，不得溢出；
- 保持 heading 层级，不新增第二个 `h1`。

## 工程约束

- Vue 3 Composition API + TypeScript；禁止隐式 `any`；
- 一个组件一个职责：视图只负责组合，数据请求/状态放 API 与 composable；
- 禁止硬编码医学示例内容；禁止 no-op 按钮；
- 不重写既有 API client，不删除现有单篇精读/问答能力；
- 若需调整旧 `PaperAnalysisView` 路由的默认渲染，确保 `documentId`/`analysisId` URL 恢复语义不丢失；
- 为新增或改变的交互补 Vitest 测试：真实 API 成功、空数组、请求失败、无 ID 输入、选择论文后跳转携带真实 ID；
- 不执行超出范围的 P1（原文定位、证据笔记、版本比较、跨论文覆盖度/差异提示）。
