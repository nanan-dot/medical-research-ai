## 2. 用户确认的问题与根因

### 问题 A：上方空白过多

当前 `/documents` 从页头到三栏工作区依次出现：

1. 全局/模块页头：`文档与知识` + 说明；
2. `知识库 / 文档库`二级 Tab；
3. `DocumentWorkspaceSummary` 中的 `文档库 / 全部知识库`；
4. `全部文档`；
5. 第二个“管理资料”入口；
6. 五项统计；
7. 单独占行的说明：`处理统计仅在选定知识源后显示。`；
8. 最后才进入三栏工作区。

这是**层级重复导致的纵向浪费**，不是简单把所有 padding 砍掉。

### 问题 B：资料范围可读性弱

当前 `DocumentScopeNav.vue` 中：

- 标题/选项约 `0.78rem`；
- 管理资料约 `0.72rem`；
- 分组标题约 `0.7rem`；
- 异常提示约 `0.66rem`；
- 范围项最小高度仅 `34px`；
- 文件夹名、异常、数量被挤在一行，名称扫描性弱。

在 1440/1600px 桌面端明显偏小，左栏不像主要范围导航。

## 3. 本轮明确目标

桌面端重构为三层纵向结构：

```text
第 1 层：文档与知识页头 + 说明 + 知识库/文档库局部 Tab（保持既有全局结构）
第 2 层：紧凑的当前范围 + 统计带
第 3 层：资料范围 / 主工作区 / 文档详情三栏
```

期望结果：

- 相比当前截图，三栏工作区整体明显上移；
- 1440×900 首屏至少多展示约 1 行文档；
- 左栏成为清晰、可点击的主要范围导航；
- 删除重复文字/入口，但不删除真实功能；
- 不伪造统计，不改 API，不恢复上传。

## 4. 具体修改要求

### A. `DocumentWorkspaceSummary.vue`：删除重复层级，压缩统计带

#### 必须修改

1. 删除独立的面包屑文案：
   ```text
   文档库 / 全部知识库
   ```
   页头和 Tab 已经表达当前位置，不需要再次重复。

2. 保留当前范围名称：
   - 无 `sourceName`：显示 `全部文档`；
   - 有 `sourceName`：直接显示真实知识源名称。

3. 删除 Summary 右上角的第二个“管理资料”入口。
   - `DocumentScopeNav` 已有“管理资料”；只能保留一处；
   - 本轮保留左栏标题右侧的入口，因为语义最接近资料范围管理。

4. 将五项统计压缩为一条紧凑统计带：
   ```text
   文件总数 16 | 已解析 — | 已索引 — | 待处理 — | 异常 —
   ```
   不要求同一行必须是纯横排文本，但整体高度必须显著低于当前实现。

5. 删除长期占用一整行的：
   ```text
   处理统计仅在选定知识源后显示。
   ```
   替代方式二选一：
   - 在不可用的 `—` 上保留已有 `title`/可访问说明；或
   - 在范围标题旁放一条短说明，例如 `跨知识库范围仅显示准确指标`，但不得再单独占满一行。

6. 统计只能使用真实字段：
   - 文件总数：真实 `total`；
   - 已解析/已索引/待处理/异常：仅在 `stats` 存在时显示真实值；
   - 全部文档无准确聚合时继续显示 `—`，严禁从当前分页推断全库统计。

#### 视觉尺寸目标（允许根据现有字体略微调整，但不得偏离）

- Summary 整体桌面高度：目标约 `70–82px`；不得超过约 `90px`；
- 顶部/底部 padding：约 `8–10px`；
- 范围名称：约 `15–16px / 700`；
- 统计标签：约 `11–12px`；
- 统计值：约 `15–17px / 650–700`；
- 不使用厚重 Card 或阴影；仅用现有细边线分隔。

### B. `DocumentScopeNav.vue`：建立清晰字体层级

#### 字号与行高

桌面端（`>=1024px`）建议：

| 元素 | 目标 |
|---|---|
| `资料范围`标题 | `14px`，`font-weight: 700` |
| `管理资料` | `12–13px`，`font-weight: 600–700` |
| “全部文档”选项 | `14px`，选中时 `600–700` |
| “知识文件夹”分组标题 | `12px`，次级色，`600` |
| 文件夹名称 | `13.5–14px`，`500–600` |
| 文件数量徽标 | `12px`，`600`，右对齐 |
| 异常提示 | `11–12px`，明确红色/警示语义 |

不要照搬 CSS 任意小数；使用清楚、统一、可维护的 rem 或 px 标度。

#### 布局

1. 左栏宽度由 `DocumentManager.vue` 的网格统一调整到约 `236–248px`；推荐 `240px` 或 `244px`，不要超过 `252px`。
2. `.scope-item` 最小高度提升到 `40–44px`；左右内边距约 `10–12px`。
3. 选中项继续使用：
   - 浅蓝背景；
   - 左侧学术蓝指示条；
   - 清晰字体权重；
   - 不只靠颜色表达，保留 `active` 状态与语义结构。
4. 数量徽标固定靠右，不与文件夹名称抢空间。
5. 文件夹异常状态不要再夹在名称与数字之间。
   推荐结构：
   ```text
   [文件夹图标] 文献                      12
                10 个异常
   ```
   或等价的两层布局。异常是来源状态，应位于名称下方或单独的辅助行。
6. 文件夹名称超长时使用 ellipsis，但数量和异常信息仍须可见。
7. `管理资料`保留为进入 `/sources` 的真实路由；不在文档库弹导入表单、不创建知识源。
8. 空态“去知识库添加资料文件夹”同步提高到至少 `13px`，并保持键盘可访问。

### C. `DocumentManager.vue`：调整网格与纵向衔接

1. 桌面三栏建议：
   ```css
   grid-template-columns: 244px minmax(640px, 1fr) 300px;
   ```
   或在现有内容下选取 `240–248px / 自适应 / 300–320px` 的合理值。
2. Summary 与 `.workspace-grid` 之间不得再有额外大 margin；视觉上应连续衔接。
3. 保持中栏空间优先；不能因为左栏放大导致表格字段被挤坏。
4. 保持现有响应式：1024px 以下转换为横向范围导航/单列工作区，不能产生页面级横向溢出。
5. 不改业务方法、API、sourceId、选中、重试、索引、AI 导航逻辑。

### D. `DocumentsView.vue`：只压缩局部内容容器，不碰全局壳

1. 当前页面容器：
   ```css
   width:min(100% - 3rem,1280px);
   padding:10px 0 48px;
   ```
2. 允许将内容最大宽度提升到约 `1380–1440px`，以更适合三栏工作台；必须保留左右安全边距。
3. 顶部 padding 可收紧，但不能修改 `AppShell`、`AppTopbar`、Breadcrumbs 或全局页面标题。
4. 不修改知识库页面容器；本轮只解决 `/documents`。

> 若上方大空白主要来自全局壳而非 `DocumentsView`，**不得越界修改全局壳**。在最终报告中说明无法在本轮白名单内消除的剩余空白，不要偷偷修改 AppShell。
