
负责模块：R1真实用户试用与修复

【来源需求】
### 固定任务

1. 导入 5 篇论文；
2. 分析 1 篇；
3. 提出 5 个问题；
4. 查看引用；
5. 导出报告；
6. 提交反馈。

### 反馈问题

- 有帮助吗？
- 哪一处错误？
- 引用支持回答吗？
- 下一步最想做什么？

### 验收

- 用户能独立完成；
- 阻塞问题修复；
- 高频错误分类；
- R2 Backlog 建立。

---

【建议文件范围】
- docs/R1_USER_TEST_SCRIPT.md
- docs/R1_USER_TEST_REPORT.md
- docs/R1_ACCEPTANCE.md
- docs/R2_BACKLOG.md
- app/modules/feedback/*
- 必要缺陷修复文件

文件路径是建议范围。若仓库实际结构不同，必须复用现有结构并说明映射，禁止创建第二套重复架构。

【接口要求】
- 复用现有反馈API；可增加匿名反馈导出

【数据与状态要求】
- 任务完成率
- useful
- citation_correct
- data_correct
- error_type
- comment

【实施步骤】
1. 准备5篇论文与任务脚本
2. 观察用户独立完成
3. 收集四问题反馈
4. 按阻塞/严重/一般分类
5. 只修复R1范围缺陷
6. 完成回归与验收

【必须处理的异常】
- 用户只给主观评价
- 测试材料过于简单
- 修复引入回归
- 临时需求导致范围膨胀

【测试要求】
- 完整用户流程
- 错误恢复
- 引用核对
- 导出
- 模型配置
- 匿名反馈导出

测试规则：
- 普通单元测试不得依赖真实云端费用；
- 外部服务使用 Mock；
- 真实集成测试单独标记；
- 实际运行测试，禁止声称未运行的测试通过；
- 数据库模型变化必须生成并审查 Alembic 迁移；
- 前端任务必须运行类型检查、测试和生产构建；
- 不得在测试、日志和响应中泄露 API Key、未发表材料或完整敏感内容。

【阶段禁止范围】
- PubMed检索
- 多论文证据矩阵
- 候选研究方向
- 完整写作系统
- LangGraph Agent
- 多向量检索
- 多用户与云端部署

【通用禁止】
- 不进行与本任务无关的重构；
- 不把所有逻辑写进 main.py；
- Router 不直接写 SQL 或调用外部 RAG；
- Repository 不调用大模型；
- Agent 不直接操作数据库；
- 不修改或删除用户原始论文；
- 不硬编码密钥；
- 不伪造论文、DOI、PMID、页码、引用、医学结论或测试结果；
- 本地模型失败不得自动切换云端；
- 不一次执行下一个工作包。

【手工验证】
1. 让用户独立执行
2. 记录屏幕或步骤
3. 复现每个错误
4. 修复后重复任务
5. 签署验收清单

【完成标准】
1. 来源需求中的验收项全部满足，或明确说明无法满足的证据与原因。
2. 自动化测试实际通过。
3. 手工验证步骤可复制执行。
4. 数据库迁移可升级，重要变更可回滚。
5. 更新 `docs/R1_IMPLEMENTATION_STATUS.md`，记录已完成、测试结果、已知限制和下一任务。
6. 给出建议 Git 提交：`test(r1): complete real-user acceptance and fixes`。
7. 完成本任务后立即停止，只说明下一任务，不执行。

【最终输出格式】
# 当前任务
# 前置条件检查
# 仓库现状
# 文件变更计划
## 创建文件
## 修改文件
## 明确不修改范围
# 实现说明
# 数据库迁移
# 实际执行命令
# 测试结果
# 未执行项目及原因
# 手工验证步骤
# 已知限制
# 安全与隐私检查
# 状态文档更新
# Git建议
# 下一任务（只说明，不执行）
```
