# FE-04：R2-WP01/WP02文献检索构建器提示词


## 全阶段共同背景

项目：医学科研智能助手平台  
当前后端进度：**R2-WP02 已完成**  
前端目标：先完成整体产品界面，再随着后端任务推进逐步替换 Mock Adapter。

必须区分三种功能状态：

- `LIVE`：仓库中已经存在并经过验证的真实接口；
- `MOCK`：高保真前端原型，使用类型安全的 Mock Adapter；
- `UNAVAILABLE`：当前不能合理模拟的能力，明确显示“待接入”，不得伪装成功。

R2-WP03及之后、R3、R4的后端能力，在仓库没有真实接口时不得擅自补写后端，不得把 Mock 医学数据包装成真实检索结果。

视觉参考文件建议放在：

```text
docs/design/医学科研智能平台界面总览.png
```

总体风格：

- 月之暗面式稳定产品结构；
- 深海军蓝左侧导航；
- 浅色论文纸张感工作区；
- Awwwards/Behance的构图与留白；
- Dribbble级组件细节；
- Nature、Science、PubMed式医学科研专业感；
- 统一右侧证据与上下文栏；
- 禁止普通后台模板、同质Card墙、廉价霓虹和无意义特效。

共同代码规则：

1. 一个文件只负责一个功能；
2. 禁止所有代码写在一个文件；
3. 每个组件独立封装；
4. 复杂逻辑添加有意义的中文注释；
5. 使用TypeScript；
6. API、Types、Store、Composable、View分层；
7. 不生成无意义代码和未来空壳；
8. 不伪造医学论文、DOI、PMID、页码、统计数据和真实接口结果；
9. 实际运行类型检查、Lint、测试和Build；
10. 未实际运行的命令不得声称通过；
11. 每轮只完成当前FE任务；
12. 完成后立即停止，不自动进入下一任务。

# 可直接复制给Codex

```text
你现在执行FE-04：R2-WP01和R2-WP02文献检索构建器。

重要边界：

- 当前后端只完成到R2-WP02；
- 只将仓库中已验证的检索需求建模、关键词、同义词、缩写和MeSH候选能力标为LIVE；
- PubMed真实结果属于R2-WP03及后续能力，除非仓库已经有真实接口，否则必须是MOCK或UNAVAILABLE；
- 不擅自实现PubMed后端。

一、页面目标

帮助医学研究生将自然语言研究主题转为：

- 结构化研究条件；
- 核心概念；
- 同义词；
- 缩写；
- MeSH候选；
- 自由词；
- 布尔检索结构；
- 可复制检索式。

二、布局

顶部：
- 大型研究主题输入框；
- 示例；
- “解析研究问题”主按钮；
- 当前功能状态。

搜索框下方：
- Population；
- Intervention或Exposure；
- Comparison；
- Outcome；
- Study Type；
- 时间范围；
- 用户可编辑的条件标签。

左侧检索构建器：
- 概念组；
- 同义词；
- 缩写；
- 自由词；
- MeSH候选；
- AND/OR逻辑；
- 排除词；
- 添加、删除、排序。

中央：
- 检索策略说明；
- 术语来源；
- 用户修改；
- 缺失信息；
- 澄清问题；
- 如果后端没有PubMed结果接口，显示“真实检索将在R2-WP03接入”。

右侧Context Rail：
- 最终PubMed检索式；
- 布尔结构；
- 字段标签；
- 预计查询范围说明；
- 复制；
- 保存草稿；
- 导出Markdown。

三、真实接口接入

必须严格根据FE-00接口清单接入：

- Query Modeling；
- Term Expansion；
- Synonym；
- Abbreviation；
- MeSH Candidate；
- Search Query Build。

不得臆造路径和Schema。

四、Mock边界

如需要展示未来PubMed结果区：

- 使用明显标注“前端结果原型”；
- 论文标题使用“演示文献A/B”；
- DOI、PMID显示“未接入”，不要编造编号；
- 不显示假引用次数；
- 不显示假期刊指标；
- 点击搜索时不得显示“已从PubMed获取”。

五、建议组件

- ResearchTopicInput；
- StructuredQueryForm；
- ResearchConditionChips；
- ConceptGroupEditor；
- SynonymList；
- AbbreviationList；
- MeSHCandidateList；
- BooleanOperatorControl；
- QueryPreview；
- ClarificationPanel；
- FeatureAvailabilityNotice；
- SearchDraftActions。

六、交互

- 用户可以编辑所有模型生成条件；
- 用户修改后标记“人工修改”；
- MeSH候选不能自动强制选择；
- 检索式变化实时预览；
- 支持撤销最近一次术语编辑；
- 支持保存草稿；
- 允许字段填写“不知道”。

七、状态

- 未输入主题；
- 解析中；
- 解析失败；
- 部分术语为空；
- 无MeSH候选；
- 后端不可用；
- 用户已修改；
- 草稿已保存；
- PubMed结果尚未接入。

八、测试

- 自然语言输入；
- 条件编辑；
- 同义词增删；
- AND/OR变化；
- MeSH候选选择；
- 检索式实时更新；
- 空输入；
- 接口失败；
- Mock边界；
- 未接入状态。

九、验收

- 当前R2-WP01/WP02能力正常接入；
- 用户看得见并能修改检索式；
- 不把未来PubMed能力伪装成LIVE；
- 类型检查、Lint、测试和Build通过；
- 更新FEATURE_MATRIX和IMPLEMENTATION_STATUS。

完成后只说明下一步FE-05，不执行。
```
