## 2. 重构还是局部重写的决策规则

## 4. 已确认必须接入的真实能力（知识库 /sources）

必须继续使用真实的知识来源接口：

- `GET /api/v1/knowledge-sources`：来源列表；
- `POST /api/v1/knowledge-sources`：创建来源；
- `PATCH /api/v1/knowledge-sources/{id}`：启用/停用；
- `POST /api/v1/knowledge-sources/{id}/sync`：同步；
- `DELETE /api/v1/knowledge-sources/{id}`：移除系统记录。

必须保留字段：名称、来源类型、授权目录、启用状态、同步状态、最近同步时间、真实错误原因。

来源类型只允许：`local_folder`、`obsidian_vault`、`temporary_import`。不要新增云盘、PubMed、Zotero、上传文件等不存在的来源类型。

## 5. 知识库页面骨架

页面必须被明确识别为「文档与知识」工作空间的二级页面之一。

1. 内容区最大宽度约 1280-1320px，桌面端左右留白稳定，不贴边。
2. 页面唯一 `h1` 为“文档与知识”。
3. 标题下的说明：`让本地研究材料成为可追溯的证据资产。`
4. 标题下放紧凑的二级 Tab：
   - 知识库 → `/sources`
   - 文档库 → `/documents`
   使用 RouterLink，当前项为钴蓝文字加 2px 底边；不是肥大胶囊，不增加第二个 h1。

## 6. 视觉系统与精确复刻要求

以参考图为目标，优先匹配层级、密度、间距、状态层次与交互位置，不要逐像素拷贝无关的顶栏/侧栏。

#### 颜色和材料

- 整体主画布：冷白或极浅灰蓝，约 `#F6F8FB`。
- 内容面：白色，边界用低对比蓝灰色，约 `#DCE5F2`。
- 标题和主要文字：深海军蓝，约 `#10213D`。
- 辅助文字：蓝灰，约 `#667995`。
- 唯一主强调色：钴蓝，接近 `#2563EB` 或现有 token 中最接近的主蓝。
- 成功：低饱和绿色；警告：琥珀；错误：红色。状态必须同时有文字和图标/形状，不能只靠颜色。
- 禁止紫色 AI 渐变、玻璃拟态、霓虹、暖米色、青绿色主题、大面积投影、营销 Hero、插画和假数据图表。

#### 字体、圆角和阴影

- 沿用项目现有无衬线字体栈；本模块禁止把 Georgia 或其他衬线当标题字体。
- H1 约 32-36px，700-750 字重；H2 20-22px；正文 14-16px；状态和元信息 13-14px。
- 输入、按钮圆角约 8px；面板约 12px；不要混用夸张圆角。
- 普通信息区只使用 1px 边框和留白，阴影近乎不可见。按钮 hover 可有极轻上浮或背景变化。
- 所有 CSS 优先使用现有 token；若当前 token 不足，只新增少量通用、语义化 token，禁止在多个组件散落硬编码色值。

#### 动效和可访问性

- 仅 120-180ms 的颜色、边框、背景和 transform 微过渡；支持 `prefers-reduced-motion`。
- 所有输入必须有 label；图标按钮有 `aria-label`；键盘可访问 Tab、开关、筛选、上传、批量操作和删除确认。
- `:focus-visible` 使用清晰的钴蓝焦点环。
- 全部主要文字和按钮满足 WCAG AA 对比度。

## 7. 知识库页面具体实现 /sources

目标是复刻参考图的结构：标题、Tab、低高度流程带、知识来源面板、来源行、页尾流程说明。

#### 7.1 流程带

放在 Tab 下方，白底、细边框、约 68px 高度，宽屏横向：

`1 知识来源  →  2 同步目录  →  3 文档解析与索引`，右侧为“仅扫描你授权的本地目录”。

- 编号是流程语义，不是装饰性章节编号。
- 用小型蓝色圆形数字、细箭头和留白组织，不能做成三张等宽卡片。
- 窄屏改为纵向说明，保留顺序和含义。

#### 7.2 知识来源面板

面板标题为“知识来源”，副标题只基于真实数据显示：`{sources.length} 个来源 · {enabledCount} 个已启用`。数据未加载时显示骨架或“正在读取知识来源”，禁止静态数字。

创建区在同一面板内，桌面端为一行三字段加主按钮：

- 名称：可见 label；
- 类型：select，默认 `local_folder`；
- 授权目录：可见 label；
- 主按钮：“添加知识源”。

平板与移动端纵向排列。提交期间禁用重复提交；保留真实错误信息。

来源列表采用参考图的“安静行”而不是现有大卡片：

- 左侧：来源类型的项目既有图标或简洁文本标识、名称、目录路径；
- 中部：同步状态、最近同步时间或真实错误；
- 右侧：同步按钮、语义化开关、移除菜单/操作；
- `scanning` 时禁止重复同步；`unavailable`、`completed_with_errors` 必须显式展示错误；
- 移除前必须二次确认，并说明“仅移除系统记录，不会删除原始目录中的文件”。

如果当前代码没有来源详情页，参考图行末箭头不得做成无效按钮。可省略，或仅在已有有效目标时显示。

#### 7.3 页尾说明

标题“同步后发生什么”。在同一浅色面板内用横向流程表达：识别新增与变更文件 → 解析支持的文档 → 建立可用于证据问答的索引。

只解释真实工作流，不显示虚构文档量、进度百分比、耗时或 AI 结论。
