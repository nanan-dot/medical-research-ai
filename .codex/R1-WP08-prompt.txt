负责模块：无答案与不确定性

【来源需求】
### 目标

减少模型编造。

### 策略

- 检索结果为空；
- 证据数量不足；
- 来源不支持问题；
- PaperQA2 返回不确定；
- 模型回答与证据不一致。

### 输出

```text
当前知识库中没有足够证据。
建议修改问题、添加论文或扩大检索范围。
```

### 验收

- 建立至少 10 个无答案问题；
- 不给出强确定性结论；
- 拒答原因可理解；
- 结果可记录。

---

【建议文件范围】
- app/modules/conversation/no_answer.py
- app/modules/conversation/service.py
- app/modules/citation/support.py
- app/core/constants.py
- tests/modules/no_answer/
- docs/R1_NO_ANSWER_POLICY.md

文件路径是建议范围。若仓库实际结构不同，必须复用现有结构并说明映射，禁止创建第二套重复架构。

【接口要求】
- 复用问答API，响应增加answer_status与uncertainty

【数据与状态要求】
- answer_status=answered/insufficient_evidence/failed
- uncertainty
- reason_codes

【实施步骤】
1. 定义拒答条件
2. 综合来源数量、来源内容和适配器状态
3. 使用保守Prompt
4. 明确区分系统失败与证据不足
5. 保存拒答原因
6. 前端显示下一步建议

【必须处理的异常】
- 阈值过严导致过度拒答
- 仅靠模型自评
- 来源存在但不支持
- 用户误以为系统故障

【测试要求】
- 无检索结果
- 低相关来源
- 问题超出论文
- 含部分答案
- 模型仍强答
- 系统错误不误报无答案

测试规则：
- 普通单元测试不得依赖真实云端费用；
- 外部服务使用 Mock；
- 真实集成测试单独标记；
- 实际运行测试，禁止声称未运行的测试通过；
- 数据库模型变化必须生成并审查 Alembic 迁移；
- 前端任务必须运行类型检查、测试和生产构建；
- 不得在测试、日志和响应中泄露 API Key、未发表材料或完整敏感内容。

【阶段禁止范围】
- PubMed检索
- 多论文证据矩阵
- 候选研究方向
- 完整写作系统
- LangGraph Agent
- 多向量检索
- 多用户与云端部署

【通用禁止】
- 不进行与本任务无关的重构；
- 不把所有逻辑写进 main.py；
- Router 不直接写 SQL 或调用外部 RAG；
- Repository 不调用大模型；
- Agent 不直接操作数据库；
- 不修改或删除用户原始论文；
- 不硬编码密钥；
- 不伪造论文、DOI、PMID、页码、引用、医学结论或测试结果；
- 本地模型失败不得自动切换云端；
- 不一次执行下一个工作包。

【手工验证】
1. 运行10个有答案和10个无答案问题
2. 人工记录混淆矩阵
3. 检查拒答文案
4. 调整规则并保存版本

【完成标准】
1. 来源需求中的验收项全部满足，或明确说明无法满足的证据与原因。
2. 自动化测试实际通过。
3. 手工验证步骤可复制执行。
4. 数据库迁移可升级，重要变更可回滚。
5. 更新 `docs/R1_IMPLEMENTATION_STATUS.md`，记录已完成、测试结果、已知限制和下一任务。
6. 给出建议 Git 提交：`feat(r1): add insufficient-evidence handling`。
7. 完成本任务后立即停止，只说明下一任务，不执行。

【最终输出格式】
# 当前任务
# 前置条件检查
# 仓库现状
# 文件变更计划
## 创建文件
## 修改文件
## 明确不修改范围
# 实现说明
# 数据库迁移
# 实际执行命令
# 测试结果
# 未执行项目及原因
# 手工验证步骤
# 已知限制
# 安全与隐私检查
# 状态文档更新
# Git建议
# 下一任务（只说明，不执行）
```
